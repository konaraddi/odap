**Ancestor (2 levels up)**:
> For those wondering what loop transformers are:
> 
> LLMs have layers of data, called weights. During inference, each layer gets computed once. Moving weights from HBM memory to the chip is a major bottleneck because to generate a token, you need to move an entire layer into the chip, compute once, move it out, move the next layer in. Hence, memory bandwidth has been the #1 bottleneck for inference.
> 
> A loop transformer optimizes this bottleneck. Instead of one layer being computed once, it will compute the same layer multiple times, increasing the model intelligence without relying memory bandwidth as much. Bandwidth is still important, but not as much anymore.
> 
> More intelligence is squeezed ...

**Parent comment**:
> Is there any easy way to explain why does intelligence increase with the same layer being replicated and computed multiple times? I know there is research that shows it as somewhat effective, but ...why?

**This comment**:
> I don't think it increases when compared to a truly deep nicely pre-trained model. But I think what these results show that there is a lot of redundancy / "empty space" left in the models (in retrospect, those giant models from just 1-2 years ago seem like a mistake alongside Chinchilla scaling and all the GWs of power and trillions of dollars the industry collectively decided to throw at compute).
> 
> For a model with the same layer depth, I believe the gradients during training have to travel back to a lower depth but still are able to squeeze enough out of the weights to be useful while rank collapse is a real issue for deep models unless one is careful about their architecture (someone can correct me here - if the loss function does not have a built-in "loop index", then the backprop has no way of knowing whether it's going through 32 layers or 4 layers 8 times). And with looping, you obviously get the lower VRAM footprint advantage.
